АНАЛИЗ АСИМПТОТИЧЕСКОЙ СЛОЖНОСТИ (Big O)

1. input_students()
   Сложность: O(1) — фиксированный массив из 7 элементов.

2. sort_by_score(students)
   Алгоритм: Bubble Sort.
   Сложность: O(n^2), где n — число студентов.

3. top3(students)
   Состоит из сортировки O(n^2) и среза arr[:3] — O(1).
   Итоговая сложность: O(n^2).
   Если использовать встроенную sorted() (Timsort) — O(n log n).

4. group_stats(students)
   Один проход по массиву.
   Сложность: O(n).

5. sort_by_id(students)
   Алгоритм: Bubble Sort.
   Сложность: O(n^2).

6. binary_search_by_id(students, target_id)
   Рекурсивный бинарный поиск, на каждом шаге область поиска
   уменьшается вдвое.
   Сложность: O(log n) — по числу вызовов.
   По памяти: O(log n) — стек рекурсии.

ОТВЕТ НА ВОПРОС
Бинарный поиск требует O(log n), потому что на каждом шаге
область поиска делится строго пополам: n -> n/2 -> n/4 -> ... -> 1.
Количество итераций равно log2(n).

Линейный поиск работает за O(n), потому что перебирает элементы
по одному и в худшем случае просматривает весь массив.

Пример из лекции: массив из 1 000 000 элементов.
  - Линейный поиск: до 1 000 000 сравнений.
  - Бинарный поиск: log2(1 000 000) ≈ 20 сравнений.
Ускорение — в 50 000 раз.

Требование: бинарный поиск работает ТОЛЬКО на отсортированном
массиве. Если массив не отсортирован, результат некорректен.ы
